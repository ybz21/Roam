设置页重构 · 搜索 + 分类树 + 一类一页

今天的设置是「7 个横向 tab，其中一个 tab 装 9 张卡」。这份稿子换成 VSCode 那套：顶上一个搜索框， 左边一棵两级分类树，右边只显示选中的那一类——不是一条从主题滚到两步验证的长流。 第 2 节的原型可以直接点、直接搜。

「通用」tab 的九张卡，从换主题一路排到两步验证——它不是一个分类，是没地方放的东西的收容所。

三条毛病

  • 找不到。 五十多项设置没有一个搜索框。「Claude 用哪个可执行文件」在通用的第三张卡里， 「镜像画质」在浏览器还是手机里全靠试。
  • 分类不成立。 七个 tab 里有一个叫「通用」的垃圾桶（9 张卡），一个叫「偏好」的只读 KV 表 （PreferencesOverview，把已经在别处能改的值再列一遍），剩下五个才是真分类。 横向 tab 还有硬上限：再加两类就得换行或者滚动。
  • 看不出改没改、写去哪。 每张卡的保存策略都不一样——有的改完即存，有的要按「保存」， 浏览器那张还要「保存并重启」。多机之后又多一个问题：这一下写到哪台机器上？页面一个字都没说。

02 新结构（可交互原型）

左边两级树（父可展开，叶子才是一页），右边只画选中的那一页，翻页不滚动。 顶上的搜索是唯一跨类的入口：搜出来的结果按类分段平铺，点一条就跳到它所在的页。 试试搜 claude、超时、密码。

原型里的控件只画样子，不真的存；蓝色竖条 + 「重置」表示这一项被改离了默认值。

为什么是「一类一页」而不是长流

  • 翻页比滚动可回溯。 一条长流里改完一项再往回找，你得凭肌肉记忆滚回去；一类一页， 位置由树决定，回来时那一页还是原样。
  • 一页装不下 = 这一类该拆。 这条约束是设计的一部分：桌面一页控制在 6 项以内， 超了就分二级（浏览器 → 启动 / 窗口），而不是让它长出滚动条。 「通用」那种九张卡的收容所，在这条规则下压根建不起来。
  • 每一页都有地址。 #/settings/node/browser 可以直接发给别人、可以被 「去设置里打开它」的按钮直接跳（比如镜像页报「Chrome 没装」时跳到浏览器页），返回键也认。 一条长流做不到这件事——锚点滚动落点会被上一次的滚动位置带偏。
  • 唯一允许滚的是搜索结果页，因为它天然跨类、条数不可控。

三区各自解决第 1 节的哪一条

区解决怎么解决的
搜索框找不到 索引 = 名称 + 说明 + 键名（claudeCommand 这种）。结果按类分段， 每条带面包屑；点一条切到那一页并高亮该行。树上同时显示每类的命中数—— 一眼看出「证书」这个词横跨安全和多机两类。
分类树分类不成立 纵向两级，没有横向 tab 的数量上限；父级只管展开，值都在叶子上。 分段标题把「值写在哪」直接写进导航。
一类一页看不出改没改 页头常驻一枚写入目标徽标（本机 · 开发机），行上用蓝竖条标出改离默认的项， 「重置」跟在名字后面。

03 分类怎么划的

树的三段不是随手起的名字，是按值真正存在哪个文件里划的——这是多机之后唯一还站得住的划法。

段存储为什么归在一起
跟着我走preferences.json ＋ localStorage 镜像 主题、语言、密度、快捷命令这些是「我习惯这样」，跟人不跟机器。今天它们只存在服务端， 于是切一台机器主题可能就变了——见下面那条待决。
这台机器config.yaml、browser-config.json、 phone-config.json、speech-config.json、环境变量 Chrome 装在哪、adb 连哪台安卓、ASR 密钥、登录口令——都是这台机器上的东西， 换台机器本来就该是另一份值。
整个集群中心的注册表 ＋ 本节点的 cluster/node.json 角色（节点/中心）、接入地址、注册令牌。这一段是唯一「改一处、多机可见」的。
一条待决：主题和语言现在跟着机器走。 它们存在服务端 preferences.json 里，切到另一台机器读的是那台的值，界面会当着面换一副样子。 建议按 WORKSPACE_MIRROR 已有的先例办：纯观感项（主题 / 语言 / 密度 / 方向簇 / 各种宽度） 以浏览器本地为准，服务端只作备份；其余仍以服务端为权威。这件事不做，「跟着我走」这一段就是空头支票。

04 一行设置长什么样

所有设置共用一种行，不再是「一项一张 Card」。Card 的边框在这里没有信息量， 五十项设置就是五十个框，反而把真正的分组线淹了。顺序固定：名字 → 说明 → 控件。

文本型

失焦即存，不给「保存」按钮——一页里五个保存按钮是五次犹豫。

枚举型 自动无头有头

三档以内用分段器，更多用下拉；两者都够窄，收在标题行右端。

危险型totp

关掉之后，只要有口令就能登录。这类项走二次确认，按钮是危险色， 和上面那些改完即存的行明确不是一种东西。

  • 能即时存的就即时存。 开关、分段器、下拉改完就写（跟今天 setPrefs 一样），文本框走失焦提交。 只有「会打断正在跑的东西」的（重启浏览器、切集群角色、改口令）保留显式按钮。
  • 键名常驻显示。 claudeCommand 既是搜索命中项，也是用户去 issue 里描述问题时的说法。
  • 徽标只在偏离时出现——「默认 关」「改完要重启」「实验性」。每行都挂满徽标等于每行都没有徽标。
  • 页级动作在页头，不占一行。 「保存并重启浏览器」「推送到会话」管的是整页而不是某一项， 摆在标题右边（连同那枚说明后果的徽标）。这条同时把行数省了出来—— 「一页 6 项」的预算不该被动作按钮吃掉。
  • 危险动作不进普通行。 「离开集群」「关闭两步验证」走危险色 + 二次确认， 和它上面那些改完即存的行明确不是一种东西。

06 怎么落地

核心是：设置项变成数据，页面变成渲染器——不这么做就没有搜索，也没法保证「一页 6 项」这条约束。

文件

文件放什么
frontend/src/settings/registry.ts 唯一的设置清单：{ id, page, labelKey, descKey, key?, control, scope, needsRestart?, read, write }。 分类树、每一页的内容、搜索索引、手机端列表全部从它生成。「常用」页存的是一串 id 引用，不是副本。
frontend/src/settings/SettingsPage.tsx 三区外壳：搜索框、树、当前页。路由 #/settings/<page>， 未知或缺省落到 common。不需要滚动侦测——没有长流要侦测。
frontend/src/settings/SettingRow.tsx 一行的渲染 + 控件分发（开关 / 分段 / 下拉 / 文本 / 标签组 / 自定义）。
frontend/src/settings/pages/*.tsx 装不进「一项一行」的复杂块：手机的 Android/iOS 双卡、两步验证的二维码流程、多机的角色卡。 以 control: 'custom' 挂进对应页，仍然吃搜索（靠 keywords）。
frontend/src/cluster/ClusterSettings.tsx 现成的，原样搬进「多机」页，不重写。

顺序

  • P1 · 换壳。 三区外壳 + registry + 路由 + 搜索，把今天七个 tab 的内容按第 3 节的表搬进去， 行为一个不改。删掉只读的「偏好」tab，换成页头的 JSON 按钮。
  • P2 · 补漏。 把今天只能靠拖、靠猜的项补进设置：信息密度、侧栏成轨、终端区默认展开、方向簇。
  • P3 · 观感项本地优先。 第 3 节那条待决落地：主题/语言/密度以 localStorage 为准， 切机器不再换脸。
i18n：registry 里存的是 labelKey / descKey，不是中文串—— 搜索索引因此必须在 t() 之后建，否则英文界面下搜不到任何东西。 npm run i18n:check 守住两份键齐全。
验收：桌面确认每一页都不出滚动条（出了就是这一页该拆），刷新后停在同一页，浏览器返回键能退回上一页； 手机档按 docs/development/web-ui-checklist.md 走真机——重点是 44px 行、搜索框吊起键盘后列表还能滚、 子页返回手势正常。
