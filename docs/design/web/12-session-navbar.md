> 图纸：[12-session-navbar/index.html](./12-session-navbar/index.html)（S0 现状对照 · S1 桌面 · S2 状态矩阵 · S3 图标表 · S4/S5 窄栏与手机 · S6 明亮主题 · 规格表）
>
> 状态：设计已定，实现落在 `frontend/src/index.css`（`.tt-tabs` / `.tt-tbar` 段）与
> `frontend/src/App.tsx`（`TI` / `AgentMark` / `TBtn` + `TerminalPane` 里的 `tabStrip` / `sessionToolbar`）。

## 1. 现状与问题

会话页顶部两行（终端标签条 + 会话工具条）是全站出现频率最高的一块 chrome——只要开着终端就一直在眼前，
但它是历次功能迭代「一个功能加一个按钮」堆出来的，从没被当成一块外壳整体设计过：

- **没有层次**：两行底色跟终端一样是纯黑，三块区域糊成一片，看不出「外壳 → 内容」。
- **图标语言不统一**：`🔔 弹框提醒`、`📁 文件`、`🎤` 是 emoji，Git 是线性 SVG，`↗`/`▲`/`▼底`/`✳`/`✸`/`×` 是字符。
  emoji 跟不了强调色、各平台字形不一，在深色栏里显得廉价。
- **控件不咬合**：antd `size="small"` 按钮 24px 高 / 6px 圆角，标签 8px 圆角、内边距又是另一套。
- **主次不分**：14 个控件平铺一行，「改会话状态」（重命名、开面板）与「只看画面」（翻页、字号、重绘）一样重。
- **选中态弱**：每个标签都描 1px 框，选中态只多一层蓝底，扫视时抓不住当前会话。

一句话：**功能没问题，观感像调试面板。**

## 2. 设计目标

| 目标 | 落到界面上 |
|---|---|
| 有层次 | 标签条 `--bg-container` → 工具条 `--bg-base` → 终端 `--bg-term`，逐层变暗，视线落到内容 |
| 一套语言 | emoji / 字符箭头全部换成内联线性 SVG：24 viewBox、15px、stroke 1.8、圆头、`currentColor` |
| 会咬合 | 标签 h28/r8，按钮 h27/r7，分段组内按钮 h23/r6；统一 12.5px 字号 |
| 分主次 | 三段断句（状态 · 会话动作 · 面板开关）+ 右侧只读工具收进浅色分段组 |
| 抓得住 | 未选中标签不描边；选中 = 蓝底 + 蓝框 + 加粗；状态点带一圈同色光晕 |

**不做**：不改任何交互语义与按钮顺序（肌肉记忆保留），不动路由/数据，不引入新依赖。
新增文案只有一条：语音按钮的「语音输入」标签（`voice.input`）。

## 3. 结构

```
会话导航栏
├─ 标签条 (.tt-tabs, 高 40)     [收起] │ [● ✳ 会话名 ×] [● 会话名 ×] …           ← 横向滑动
└─ 工具条 (.tt-tbar, 高 37)     ● 已连接  [✳Claude][◉Codex] │ [tmux▾][新标签][重命名]
                                 │ [提醒][文件][Git][语音输入] ──► [↑ ↓] [A− A+] [⟳ ⛓]
                                                                  └── 分段组：只读工具
```

- **左段（状态）**：连接状态点 + 文案；Claude / Codex 视图切换（该 Agent 在跑时才出现，各自的品牌色）。
- **中段（会话动作）**：tmux 菜单、在新浏览器标签打开、重命名 —— 会改会话或开新窗口的动作。
- **中段（面板开关）**：弹框提醒、文件、Git、语音输入 —— 开关型，开启态上强调色。语音按钮原来只有一个 🎤 图标，认不出是干什么的，补上「语音输入」文案（新增 i18n key `voice.input`）。
- **右段（只读工具）**：上翻 / 回底、字号 −/+、重绘 / 重连，各成一个分段组，纯图标 + Tooltip。

## 4. 关键决策

**为什么右侧改纯图标？** 这 6 个是「看画面」的辅助，不该跟改状态的动作抢注意力；
窄栏和手机上它们最先被挤出视口，图标化后能多留一半空间。原有 i18n key
（`terminal.scrollHistory` / `toBottom` / `redraw` / `reconnect` / `decreaseFont` / `increaseFont`）
继续作为 Tooltip 标题，文案没有丢。`terminal.bottomShort` / `redrawShort` / `reconnectShort`
三个短标签 key 因此不再被引用，保留在词表里（i18n 审计只查缺失不查冗余）。

**为什么默认态无边框？** 一行十几个控件，人人都描边等于人人都不突出。默认安静、hover 才浮起、
开启才上色，是让重点冒头的唯一办法（同 VS Code / Linear 的做法）。

**强调色怎么给？** 布局与 hover 走 CSS 类，开启态的颜色由行内 `style` 传 `tone`（会话蓝 `#58a6ff`、
Codex 绿 `#10a37f`），底色/描边用 `tone + '1f'` / `tone + '59'` 的 8 位十六进制透明度——
避开 `color-mix()` 在旧 WebView 上的兼容问题。

**Agent 标记**：`✳` / `✸` 两个字符字重与基线都对不齐，改成同尺寸内联 SVG——
Claude 为六芒火花，Codex 为同心环，可跟随 `currentColor`。

## 5. 响应式

- 两行都是**单行横向滑动**（不换行、隐藏滚动条）。工具条本来就有这条规则（`.tt-session-toolbar`），这次一并给标签条。
- 触屏（`pointer: coarse`）标签的关闭按钮**常显**——没有 hover。
- 手机全屏覆盖层里的「收起」就是返回入口（关掉覆盖层），保留在标签条最左。
- 切换标签后当前标签自动滚回可视区（`scrollIntoView({block:'nearest', inline:'nearest'})`）——窄栏/手机上开五六个会话时，原来切过去看不到自己在哪一格。

## 6. 主题

颜色全部走 CSS 变量，黑白主题自动跟随；只有强调色与状态点（绿 `#3fb950` / 琥珀 `#d29922` / 红 `#f85149`）
硬编码，两套底色下都验证过对比度。
