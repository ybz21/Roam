桌面版：概览 / 项目 / 会话

手机版刚把三页的分工定完（概览＝时间 · 项目＝空间 · 会话＝全集），但桌面沿用的是同一批组件， 于是桌面成了「更宽的手机」：列表被拉到 1174，内容还贴在左边，时间还贴在右边，中间是空的。 1440×900（侧栏 224）实测：

  • 概览会话行宽 838，名称右缘到时间左缘 570px 是空的（占行宽 68%）
  • 状态条宽 1174，里面只有 82px 内容——1092px 是一枚空胶囊
  • 会话页每行内容右缘 x=636，操作区起点 x=1333，中间 697px 是空的
  • 概览左栏内容到 y=590 就结束，视口 900——下方 310px 空着，右轨却排到 992
  • 项目页 4 个 0 任务的项目，占掉 467px 的卡片网格

宽度没有变成信息，变成了空气。

桌面四条原则

  1. 对齐成列。同类信息落在同一个 x 上，眼睛竖着扫一列；现在是每行左右横跳 570–700px。
  2. 中间那段宽度要给信息，不给空气。桌面每行比手机多一列——「它在哪」（⎇ 分支 / 工作目录）。 这是手机放不下、桌面放得下的东西，也是桌面版存在的理由。
  3. 破坏性动作不常驻。关闭 只在 hover 该行时出现（仅 data-pointer:fine）； 12 行 12 个红字，是界面在冲用户喊。
  4. 桌面行高 36–40，一屏放得下更多。44 是粗指针的命中下限、不是桌面的目标值； 会话条数手机 8 条、桌面 12 条。

四、自审：画完之后自己挑的毛病

  1. 会话页把「1 窗口」和「创建时间」删了，得说清规则。窗口数 99% 的会话都是 1，常驻就是一列噪声—— 只在 >1 时才显示；创建时间进名称的 title，列表里只留「最后响应」（排序默认也是它）。
  2. 名称列吃掉了全部富余，项目列前面又空出 150px。初版名称列是 1.3fr、位置列 1fr， 富余全落在名称右边——正是刚批评过的毛病换了个地方。改成名称 1fr / 位置 1.25fr： 富余给等宽字体的路径，它多一点就能少截一截。
  3. 概览「位置」列原本定死 296。只有 ~/codes 的行会空出一大截。收到 260， 多出来的给名称。列内偶尔短是列对齐的成本，可以接受；但不能宽到看着像空列。
  4. 「其他项目」在筛选态下必须整块消失。用户点了「活跃 8」，页尾还挂着 4 个不活跃项目就是自相矛盾—— 它只在「全部」下出现。
  5. 状态数字挪进页头后，别看着像装饰。它们现在仍然是导航入口（点进项目页）， 所以 hover 态、手型、44 命中区一个都不能少——挪位置不等于降级成统计文本。
  6. hover 才出现的操作对键盘用户是隐身的。除了 :hover 还要 :focus-within， Tab 到那一行时同样浮出来；粗指针档（平板）保持常驻，那里没有 hover。
  7. 会话页的标记列要装得下两枚标。「待确认 + Claude」是最常见的组合， 74px 只够一枚——放宽到 132，超出的（蜂群）折进名称行的 title。
  8. 落地时才发现的：位置列会和项目列说同一句话。非 git 项目的会话没有分支， 位置只能写工作目录，而那个目录就是左边项目列那个项目的目录——两列念同一件事。 规则改成：有分支写分支；没有分支且工作目录 ≠ 项目目录才写目录；相同就留空。 于是这一列只在「它确实在别处」时才出声。
  9. 落地时才发现的：两行排法不是「手机专属」，是「窄 Canvas 专属」。 桌面拉开终端分栏后 Canvas 同样会窄到 900 以下。所以两行栅格写成基础排法、 七列写成 @container 覆盖——按视口档位写就会在分栏态露馅。
