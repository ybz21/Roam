三、概览页：另一个毛病

五、自审

  1. 页名到底留不留？第一版我把「项目」也删了，只留筛选条——毕竟侧栏在高亮。 但工具条是 sticky 的，往下滚之后屏幕上就再没有任何字说明这是哪一页； 而项目卡和会话卡在余光里长得很像。留，但降到 19px 并入同一行—— 它的作用从「标题」变成「sticky 的锚点」。
  2. 总数放在页名后面会不会和「全部 12」重复？会，实测就是同一个数。 去掉页名后面的计数，「全部 12」那枚 chip 已经是它。（这一条在图纸里就改掉了。）
  3. 搜索挪到右边，会不会不好找？桌面用户找搜索的顺序是「先看右上角工具区」， 而且 ⌘K 全局搜索本来就在顶栏正中。左端留给筛选是因为 筛选是「在看什么」，属于内容；搜索是「怎么找」，属于工具。
  4. 说明句真的能删吗？它对第一次打开的人有用。折中：进页名的 title， 鼠标悬停可见；真要做新手引导，那是引导的事，不该常驻占一行。
  5. 会不会和刚做完的 Inspector 抢宽度？不会——页头是 Canvas 内部的一行， Canvas 变窄时筛选 chip 先横向滚动（手机档已经是这个行为）， 再窄就是 Canvas 让位，那时整页都不在了。
  6. 概览把日期挪到标题下面，会不会显得日期不重要了？本来就不重要—— 它是定位信息不是行动信息。真正的判据是：删掉它用户会不会缺什么。 答案是「大概不会，但保留成本只有半行」，所以合进 meta 行而不是删掉。
  7. 状态条全为零时，概览的 meta 行会不会变空？会。所以 meta 行在没有任务时 退回「还没有任务在跑」那句（overview.sublineIdle 已有）， 不能只写个日期在那儿——那时首屏就真的什么都没说。
