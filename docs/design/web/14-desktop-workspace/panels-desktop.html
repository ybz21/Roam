桌面版面板：Git / Worktree 进 Shell

手机那轮把 Git/Worktree 收进了全屏二级页（#149），桌面是刻意冻住的——那一轮的验收标准就是「桌面逐像素不变」。 但桌面本身有问题，而且比手机那份更糙：同一个面板有四种壳，其中一种会把终端盖掉 70%。

根因只有一句：这些面板浮在 Workspace Shell 之上，不参与 Canvas / Dock 的尺寸契约（14 §4.2）。 浮层只会「盖」，不会「让」。手机上正确答案是整页（已做）；桌面上正确答案是——成为 Shell 的一列。

三、契约

场景规则理由
先从 Dock 借Canvas ｜ Dock(借窄) ｜ Inspector 判据用 Dock 的下限：workspace − 480 − inspector − 两条 rail ≥ 560。 成立就把 Dock 借到刚好（不低于 480、不超过用户拖出来的宽度）。 实测 1920：终端 794 → 688，三列都在
借不够就让 CanvasDock ｜ Inspector（页面整个让掉） 此时 Dock 用回原宽、终端一寸不变——实测 1440：593 → 593，只是整体左移， 所以连 fit/SIGWINCH 都不触发
无终端Canvas ｜ Inspector 两列224+560+8+420 = 1212，1280 就够
905–1279（expanded）Inspector 走覆盖式（同 Dock 的 overlay 语义）+ 遮罩这一档本来就没有三列的空间，与 13 §13.1 一致
<905（phone）全屏二级页（#149 已实现）不变
同时只有一个Git 与 Worktree 互斥，后开替换先开否则又回到「抽屉盖面板」
不带遮罩≥1280 的两种形态都不加遮罩遮罩 = 模态 = 「先关掉才能干别的」，而 Git 恰恰要边看边干

四、自审：画完之后自己挑的毛病

  1. Inspector 放哪一侧？第一版我画在 Canvas 和 Dock 之间（页面｜Git｜终端）。 问题是每次开关 Git，终端的起点都会横向平移——终端最忌讳这个，宽度一变就 fit → SIGWINCH → tmux 整屏重排，肉眼是闪一下。放到最右之后，开关 Inspector 只让终端变窄，起点不动。 （变窄仍会 fit 一次，但比「被整个盖住」强得多，也比「盖住 + 起点平移」少一次。）
  2. 「Canvas 让位」会不会太粗暴？另一个方案是 Inspector 浮在 Canvas 上、Dock 不动—— 但那正是今天项目页那份的做法，也就是这一稿要治的病（浮层只会盖）。 折中方案是让位后顶栏留一枚「↩ 显示页面」，并且这个让位复用已有的 Focus 态， 不新增第五种空间状态——⌘⇧J 本来就是它。
  3. Git 与 Worktree 互斥，会不会挡住「从 Git 里点 worktree 徽标」这条路？会。 今天是 Worktree 抽屉盖在 Git 面板上（1300 盖 1200）。互斥之后那一跳会替换掉 Git 面板， 返回时要能回到 Git——所以 Inspector 需要一个「上一个面板」的返回箭头， 语义与手机二级页的 ← 一致。这条不做的话，从 Git 跳 Worktree 就是单程票。
  4. 720 这个分栏阈值是拍的吗？不是：280(列表) + 8 + 400(diff 最窄可读) + 32(padding) ≈ 720。 低于它硬分栏的话 diff 会窄到每行都折，还不如盖成第二层。
  5. 「不带遮罩」有代价。没有遮罩，用户可能不知道点外面不会关掉它。 所以 Inspector 必须常驻一个 ✕ 和 Esc，并且状态记忆——下次打开还在，不需要每次找关闭。
  6. expanded 档（905–1279）我原本想跳过。但那一档今天也会被 420 浮层盖住终端覆盖面板， 问题一模一样。既然 Dock 在那一档已经是 overlay，Inspector 沿用同一套语义即可， 不额外发明。
  7. 「↩ 显示页面」那枚按钮是多余的。我在 1280–1639 那帧画了它，想着让位之后总得有路回去。 但让位的原因是空间真的不够——按下去除了关掉 Inspector 没有第二种可能， 而关闭本来就有 ✕ 和 Esc。删掉，不做。
  8. 三列门槛写成一个固定数是错的。初稿写「≥1640 三列并存」并画了 1680 的图， 实测 1680 上 Canvas 仍然让位——因为默认 dock 是 42vw（1680 上 = 705）， 而 1640 那个数假设的是 dock 取下限 480。判据必须按实际宽度算，不是断点。
  9. 「让页面，不让终端」这条我写得太绝对了。照它实现之后实测：1920 上打开 Git， 页面照样整个消失——因为默认 Dock 是 42vw（1920 上 806），拿它去判永远凑不齐三列。 而在 1920 上「终端窄 13%（794→688）换页面留在原地」显然更划算，那正是买大屏的理由。
    改成两步：先从 Dock 借宽（不低于 480、不超过用户拖出来的宽度）， 借不够再让 Canvas——让位时 Dock 用回原宽，终端一寸不变。 原来那句话真正想守的是「终端不能被盖住」，不是「终端一像素都不能动」。

五、分期（已全部落地）

  1. P1 ✓：Inspector 作为 Shell 的第三列 —— useWorkspaceLayout 加宽度/开关， InspectorColumn 出列与 rail，AdaptivePanel 桌面分支改成 portal 进槽位； Git 两个调用点 + Worktree 接上；取消遮罩；放不下时先借 Dock 再让 Canvas。
  2. P2 ✓：Inspector ≥720 面板内分栏（容器查询），.tt-file-detail 那第四种壳退场。
  3. P3 ✓（免费得到）：非栈顶的面板是藏起来而不是卸载，所以关掉栈顶自然露出下面那个—— 「从 Git 跳 Worktree 再回来」不需要额外做返回箭头。宽度仍是一个（不按面板类型分别记）： 三种面板的内容密度接近，分开记只会让「上次拖的宽度」变得不可预测。
  4. P4 ✓：文件树也进 Inspector，FloatingFileDrawer 整个删掉。 至此「四种壳」全部收敛成一种，文件 / Git / Worktree 三者互斥。

六、落地时踩到的一条

容器查询不能挂在要被它改样式的那个元素上。第一版我把 container-type: inline-size 写在 .tt-git-root 上，然后用 @container (min-width:720px){ .tt-git-root{flex-direction:row} } 去切它自己—— 实测：detail 的 position 切了（它是后代），root 的 flex-direction 没切。 容器查询只作用于后代。改成把容器挂在 Inspector 那一列的槽位上 （container-name: inspector），面板整体就都是后代了。 顺带一个好处：手机档没有这一列，查询自然不匹配，diff 退回覆盖式——不用再写一条 data-size 分支。
