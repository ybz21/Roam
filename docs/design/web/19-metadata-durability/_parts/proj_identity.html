5.2 身份是不可变 id，目录只是可变属性

早期版本拿「目录名 slug + 路径 hash」当 key，mv 一下项目目录身份就变、 置顶和显示名得靠合并搬家。现在 id 入册时生成、永不改，dir 只是一个字段： 

项目 id   2026-0728-1202-30xe      // 不可变，一切 URL / 偏好 / 书签的 handle
dir       /home/ai/codes/ttmux     // 可变属性：mv 目录、worktree 子目录归位仓库根，都只改这里
aliases   老 key → 现行 id          // v1 的 hash key、被合并掉的 id 都记在这，老链接不失效

SetDir(key, newDir) 两种走向：
  newDir 没被占用        → 改 dir，id 不变，偏好一个不丢
  newDir 已有别的条目     → mergeInto 合并（置顶/显示名/最早 firstSeen 取「用户意志」的并集），
                          旧 id 落进 aliases，指向旧 id 的别名一起改指

自愈也挂在这条路上：聚合时若发现条目的 dir 指向的是仓库子目录 （历史脏数据或瞬时误判），用 ResolveRepo 归位到仓库根 —— id 不变， 所以置顶、显示名、默认 agent、老链接全都不动。

5.3 存了什么

字段含义丢了会怎样
id不可变身份所有 #/projects/<id> 链接失效
dircanonical 目录（git 项目 = 主仓库根）条目等于没有
origin'' discovered · 'user' 显式创建一等对象降级成可自动退场
pinned · displayName置顶、显示名用户意志丢失（排序乱、名字回退成目录名）
defaultAgent · defaultBase新任务默认用哪个 agent、从哪个分支切每次开任务都要重选
firstSeen · lastSeen入册 / 最后一次被看见（分钟粒度刷新，避免每轮写盘）排序与「最近活动」失准
lastSessionAt最后一次有会话的时刻 —— 退场判据看它退场规则退回「此刻有没有会话」，重启即全灭

另有一份不是真相源的旁证：activity.log（JSONL，只增不改，超 5MB 轮转一代）。 它记「任务 → 动作（merged / discarded / cleaned）→ 统计」的摘要，用来在 worktree 删除后 还能追溯「这个任务去哪了」。丢了只损失摘要，不影响任何判定。
