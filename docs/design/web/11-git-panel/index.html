目标：把现在这个「只能看改动 + 最近 20 条提交纯文本」的面板，做成能看懂整棵树、能就地动手的 Git 工作台。 三条主线：提交树（真正的 DAG 泳道图，不是列表）、分支（本地/远端/标签/储藏 一屏管全）、改动（保留现有提交流，补冲突态）。 面板宽度仍是 min(420px, 92vw)，所以每一处都按 420 宽先跑通，再谈桌面加宽。

G6 要点 · ① Git 面板「分支」页在本地/远端/标签/储藏之外再加一段 Worktree——同一个仓库的引用清单里，worktree 不该缺席。 ② 该段的行点一下同样是「在提交树里定位」，⋯ 菜单里是：进入会话 / 对比 base / 合并回 base / 删除。 ③ 当前所在的那个 worktree 在段内高亮（就是「你在这」），与分支页里当前分支的高亮同一套视觉。 ④ 三处展示不重复造轮子：项目页管任务，Git 面板管引用，抽屉只管跨仓库。
后端接口增量（其余复用现有 /git/status /git/diff /git/stage /git/commit /git/op）
端点用途要点
GET /git/graph提交 DAG返回 hash / parents / refs / 作者 / ISO 时间；--date-order 保证顺序稳定，泳道在前端算。参数 limit / skip / scope / q。
GET /git/refs分支页数据本地分支（含 upstream 与 ↑↓、gone、被别的 worktree 占用）/ 远端分支 / 标签 / 储藏，一次拿全。
GET /git/show提交详情元信息 + 完整信息 + 文件清单（numstat ∪ name-status），合并提交按 --first-parent。
GET /git/diff?rev=历史差异现有端点加一个 rev 参数：看某个提交里某个文件的差异。
POST /git/action本地引用写操作白名单 action：checkout / branch-create·delete·rename / merge / rebase / reset / revert / cherry-pick / tag-* / stash-* / abort / continue / push-branch。失败时回 state + conflictFiles，前端直接引导去「改动」解冲突。
GET /git/status（增量）补 upstream / state / conflicts：state ∈ merge|rebase|cherry-pick|revert|bisect，驱动状态横幅。
泳道配色 · 按道号循环取，深色底与浅色底都验过对比度；提交行的短 SHA 用所在道的颜色，眼睛能把「这条提交属于哪条线」一眼串起来。
落地约束 · ① 全部文案走 i18n（git.graph.* / git.refs.* / git.detail.* / git.action.*），中英同步补齐。 ② 危险动作三件套：reset --hard、删除未合并分支、放弃改动——一律 modal.confirm + danger 按钮，文案带对象名。 ③ worktree 会话的「对比 base」tab 与底部「合并回 base」操作条原样保留，本次不动。 ④ 提交行固定 46px；单次默认取 150 条，「加载更多」按 skip 翻页；泳道超过 8 条时压缩道宽，右侧文字区不被挤没。 ⑤ 本页泳道图由页内脚本按落地要用的同一套算法实时计算——图纸即算法验收用例。
