浏览器页头重做 —— 让它像个浏览器

现在的浏览器页头是一堆控件排排坐，不是一个浏览器：五种 antd 控件五种语言， 「前往」是个实心蓝按钮抢走了地址栏的注意力，四枚清晰度按钮平铺在第四行， 「外部打开」被挤到第五行独占一整行。它没有主角——而浏览器的主角只有一个：地址栏。 这一稿按真浏览器的做法重排：一个 omnibox 当主角，其余全部退成图标或收进菜单， 手机上标签条换成「标签数字 + 抽屉」，Roam 特有的状态（智能体模式 / 连接与画质 / 设备） 收成一条可点的状态芯片条。

2 · 真浏览器是怎么排的

  • 一个 omnibox 独大：胶囊形、占满整行剩余宽度，左侧一枚状态徽标（锁 / 安全信息）， 右侧一枚就地操作（刷新 / 停止）。没有「前往」按钮——回车就是前往。
  • 标签变成一个数字：Chrome / Safari 手机版都是「⧉ 3」一枚方框数字，点开是整页的标签卡片， 不是挤在顶上的横条。
  • 低频动作全在 ⋯ 里：桌面版、开发者工具、分享、书签……手机浏览器的顶栏永远只有 四个可点目标：后退 / 地址栏 / 标签 / 菜单。
  • 状态不占控件位：连接、证书、翻译提示都是地址栏内部或下方的小徽标，不做成按钮排在旁边。
Roam 比真浏览器多三样东西，它们不能塞进 ⋯ 里藏起来，因为它们是状态不是动作—— 人需要一眼看见「现在是谁在开车、连没连上、画面多清楚、模拟的是哪种设备」： 智能体模式 / 连接与画质 / 设备。所以主行之下加一条 26px 的状态芯片条： 它们平时是三枚小 chip（只读一眼），点开才是控制面板。

5 · 新版 · 桌面

桌面不是「手机版拉宽」。横向有余量，就把手机上收起来的东西平铺回去：前进、主页、 指标数字、标签条全部露出来；但语法一个字都不改——还是那个 omnibox 当主角、 状态还是那几枚芯片、低频动作还是那个 ⋯ 菜单。两端的区别只有「谁露在外面」。

5.1 桌面现在也乱

  • 导航簇不用 Button.Group。四枚连体按钮是 90 年代工具栏语言，跟这一页别的圆角对不上； 改成四枚独立的 32×32 图标钮，间距 4，靠 hover 底色分组。

5.5 窄桌面与分栏：三档收纳

浏览器页会被塞进分栏（会话页右栏、Focus 布局），容器可能只有 700–900。 按容器宽度收，不是按窗口——分栏里窗口很宽但容器很窄，读 innerWidth 必然判错。

6.2 桌面上的手机镜像页

桌面上舞台两侧本来就是大片黑边（竖屏画面 + 横向容器）。按键条不再占一整条， 改成浮在画面底部的胶囊——跟着设备走，而不是跟着页面走；黑边还给画面。

redroid
▟
  • 按键条随平台换：Android 三键（返回 / 主屏 / 多任务）、iOS 三键（主屏 / 锁屏 / Siri， iOS 没有系统返回键）。今天已经是这么分的，形态跟着改就行。
  • 浮层不吃画面事件：胶囊本身 pointer-events:auto，容器 none—— 否则底部一条 40px 的死区，点不到画面里的东西（xterm 那个透明层坑的同款）。
  • 手机档贴底成实条：392 的屏上画面已经顶到边，浮层会压住内容；实条 + 安全区内边距更稳。
  • devbox 不可编辑——它是身份不是输入。想换设备走状态芯片里的「设备」， 跟浏览器页换 URL 是两回事，别为了对称硬做成输入框。
