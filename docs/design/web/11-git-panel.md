# 11 · Git 面板重设计：提交树 / 分支 / 操作

> 图纸：[11-git-panel/index.html](./11-git-panel/index.html)（G1–G6，泳道图由页内脚本按落地算法实时计算）
> 现状对照：[07-worktree/w3-git-panel.html](./07-worktree/w3-git-panel.html)
>
> 状态：已实现。后端 `backend/api/git_graph.go`（含 `git_graph_test.go`），
> 前端 `frontend/src/git/*` + `GitPanel.tsx` + `Projects.tsx` 的 Worktree tab。

## 1. 现状与问题

现在的 Git 面板（`frontend/src/GitPanel.tsx`）是「VSCode 源代码管理」的最小复刻：

- 只有**改动**一件事：暂存 / 取消暂存 / 放弃 / 提交 / push·pull·fetch·sync。
- 历史是一段**纯文本列表**——`git log -n 20` 的 subject + author + 相对时间，没有拓扑、没有分支归属、点不开。
- **完全没有分支概念**：看不到分支清单，切不了分支，建不了分支，看不到 ahead/behind 明细；标签、储藏更是没有。
- 仓库卡在 merge / rebase 中间态时面板**毫无表示**，用户只能回终端 `git status` 才知道发生了什么。

结果是：面板能干的事，终端里两行命令就干完了；面板干不了的事（看清一棵树），恰恰是图形界面最该有优势的地方。

## 2. 设计目标

一句话：**让用户在面板里看懂整棵树，并且就地动手。**

| 目标 | 落到界面上 |
|---|---|
| 看懂树 | 真正的 DAG 泳道图，分支/标签/远端徽标长在提交行上，8 色泳道 + 短 SHA 同色 |
| 看懂一个提交 | 点提交 → 详情列：元信息 + 完整提交信息 + 文件清单(+n/−n) → 点文件看差异 |
| 管得住分支 | 本地 / 远端 / 标签 / 储藏 一屏摊开，切换、新建、合并、变基、删除都在行尾菜单里 |
| 出事能自救 | merge/rebase/cherry-pick 卡住 → 顶部横幅 + 冲突文件置顶 + [继续] [中止] |
| 手机能用 | 420 宽先跑通；⋯ 是主入口（没有右键），菜单走底部动作面板 |

另外把**项目里的 worktree 怎么展示**一并收进来（§8）——同一套泳道语言，从提交树延伸到并行任务。

**不做**：不做提交图的拖拽变基、不做交互式 rebase、不做 PR/GitHub 集成、不改 worktree 的创建/合并/删除后端逻辑（只改展示与入口）。

## 3. 信息架构

```
Git 面板
├─ 头部       分支芯片(点开=分支切换器) · ↑↓同步 · upstream · ⟳ · ⋯ · ✕
├─ 状态横幅   仅在 merge / rebase / cherry-pick 卡住时出现 → [继续] [中止] + 冲突文件数
├─ 改动      提交框(可修订/提交并推送) · 已暂存 / 改动 / 未跟踪 · 冲突组置顶
├─ 提交树    搜索 + 全部分支⇄当前分支 · 泳道 DAG · 行内 ⋯ / 右键菜单 · 加载更多
├─ 分支      本地分支(↑↓ upstream) / 远端分支 / 标签 / 储藏 · 行内切换 + ⋯ 菜单
└─ 对比 base  仅 worktree 会话保留（现状不变）

详情列（二选一，桌面贴面板左侧 / 手机整屏推入）
├─ 文件差异   来自「改动」的文件行
└─ 提交详情   元信息 + 完整提交信息 + 文件清单 → 点文件看该提交的差异
```

## 4. 提交树

### 4.1 泳道算法

后端只出**线性序列 + parents**（`git log --date-order`），拓扑连线全在前端算
（`frontend/src/git/graph.ts`）。这样换搜索词、切「全部/当前分支」都不用后端配合。

每行拆成上下两个半格：上半格收「从上面下来的线」，下半格发「往父提交去的线」，节点画在交界处。
任意交叉/汇合都用同一套规则画出来，不维护跨行状态。

关键规则：

1. 提交落在**正在等它的那条道**上；没有就占一个空位。
2. 第一父继承本道；其余父找已有道汇合，找不到就开新道。
3. **两个孩子共用一个父**时，父那条道是「已存在」的——必须单独记 `parentLanes`，
   否则光比 before/after 差异会把第二个孩子连过去的那根线漏掉。
4. 行高固定 **46px**：固定行高是连线跨行对齐的前提，不能改成自适应。
5. 泳道色按**道号**取（8 色循环）；提交行的短 SHA 用所在道的颜色，眼睛能把「这条提交属于哪条线」串起来。
6. 泳道超过 8 条时压缩道宽（最低 9px，总宽封顶 132px），保证右侧文字区不被挤没。

节点样式：普通提交实心圆，**合并提交空心圈**，HEAD 外加一圈光环。

### 4.2 交互

| 操作 | 结果 |
|---|---|
| 点提交行 | 选中 + 打开提交详情列 |
| 行尾 ⋯ / 右键 | 同一份菜单（手机没有右键，**⋯ 是主入口**） |
| 搜索 | 走后端 `git log --grep --fixed-strings -i`，不是前端过滤已加载的那几条 |
| 全部分支 ⇄ 当前 | 对应 `--all` 开关 |
| 加载更多 | 按 `skip` 翻页，默认每页 150 条 |

提交菜单：查看详情 / 复制 SHA / 从此提交新建分支 / 在此打标签 / 切换到此提交(分离 HEAD) /
挑拣(cherry-pick) / 回滚(revert) / 重置当前分支到此(soft·mixed·hard)。

## 5. 分支页

四段一屏，不做折叠——420 宽的面板里再加一层折叠只会增加点击成本。

- **本地分支**：当前分支高亮 + 左侧色条；带 ↑↓、upstream 丢失标 `gone`、被别的 worktree 占用标 `wt`。
- **远端分支**：`origin/HEAD` 过滤掉（符号引用，列表里没意义）。
- **标签**、**储藏**：储藏段标题右侧一个 ＋ 直接「把工作区收进储藏」。

**分支行点一下不是切换分支**，是「在提交树里定位这条分支」——切换收在行尾 `⤓`，防手机误触。
行尾 ⋯ 菜单：切换 / 合并到当前 / 变基到此 / 重命名 / 推送(-u) / 删除（未合并时要 `-D` 二次确认）。

## 6. 提交详情

- 桌面：抽屉里**向左长出来的第二层**，与文件抽屉的「文件树 ｜ 预览」同一份 `<InspectorLayers>`：
  改动列表钉在抽屉右缘不动，详情从它左边长出来，抽屉外缘跟着两层之和向左让位（详情默认 620、
  列表 320，两层各自记宽、中间一条可拖的分界）。**不是弹窗**，也不是在固定宽里对切——
  对切会让你正看着的那一列自己跑到左半边去。
- 抽屉外缘的上界由 Shell 按终端让出的余量给。放不下两层（< 220 + 400 + 5）时详情**盖住**列表，
  标题栏左上给「←」：宁可少一栏，也不要开出一栏读不了的 diff。
- 窄屏（< 900px）：同样是「盖住 + 左上角返回箭头」，不叠浮层——92vw 的抽屉上再叠一层会两侧各露一条缝。
- 文件清单点开的差异**停在同一列**，标题栏左侧变「← 返回文件」，不再叠第三层。
- 合并提交的差异按 `--first-parent` 算，标题里明说，避免「合并提交看起来改了几百个文件」。
- 父提交 SHA 可点，直接跳到那条提交的详情——这是在树里「顺藤摸瓜」的关键动线。

## 7. 后端接口增量

其余复用现有 `/git/status` `/git/diff` `/git/stage` `/git/unstage` `/git/discard` `/git/commit` `/git/op`。

| 端点 | 用途 | 要点 |
|---|---|---|
| `GET /git/graph` | 提交 DAG | 返回 hash / parents / refs / 作者 / ISO 时间；`--date-order` 保证顺序稳定。参数 `limit` `skip` `scope` `q` |
| `GET /git/refs` | 分支页数据 | 本地分支（upstream + ↑↓ + gone + worktreepath）/ 远端分支 / 标签 / 储藏 / remote 名，一次拿全 |
| `GET /git/show` | 提交详情 | 元信息 + 完整信息 + 文件清单（numstat ∪ name-status），合并提交按 `--first-parent` |
| `GET /git/diff?rev=` | 历史差异 | 现有端点加一个 `rev` 参数 |
| `POST /git/action` | 本地引用写操作 | 白名单 action，见下 |
| `GET /git/status` | （增量） | 补 `upstream` / `state` / `conflicts`，驱动状态横幅 |
| `POST /git/commit` | （增量） | 补 `amend` / `all` |

`/git/action` 白名单：`checkout` `branch-create` `branch-delete` `branch-rename` `merge` `rebase`
`reset` `revert` `cherry-pick` `tag-create` `tag-delete` `stash-push` `stash-pop` `stash-apply`
`stash-drop` `abort` `continue` `push-branch`。

约束：
- 所有 ref/hash 参数拒绝 `-` 开头（挡参数注入），其余交给 git 自己校验。
- 远端网络操作仍走 `/git/op`（已有 120s 超时与 `GIT_TERMINAL_PROMPT=0`）。
- 失败时回 `{ code, message: git 原始输出, state, conflictFiles }`，前端直接引导去「改动」解冲突。

## 8. 项目里的 worktree

图版 G5 / G6。

### 8.1 现状问题

项目页的 Worktree tab 现在是「一排 Tag ＋ 三个按钮」，而三个按钮全都是**跳去别的面板**：
`对比 base` 跳 Git 面板（跳过去还得自己找到那条 worktree）、`合并回 base` 和 `删除` 跳 Worktree 抽屉。
而且看不出**它们彼此和主干的关系**——只有 ↑n，没有落后多少、没有是否已合入。

同时 worktree 在三个地方各有一套展示（项目页 tab、Worktree 抽屉、Git 面板的徽标 + 对比 base），职责重叠。

### 8.2 分叉图

一句话：**worktree 就是「被检出到别处的分支」，那就把它画在树上。**

项目页 Worktree tab 顶部用与提交树同一套泳道语言画一张**分叉图**：主干一条竖线贯穿全表，
每个 worktree 从主干分叉出去。「都是从 main 拉的、各自跑多远」不用读字。

状态编码在**节点形状**上，不靠 Tag 文字扫：

| 节点 | 含义 | 判据 |
|---|---|---|
| ● 绿（带光环） | 有会话在跑 | `sessions.length > 0` |
| ● 琥珀 | 孤儿待收尾 | 无会话 ∧ (`committedAhead > 0` ∨ 脏) |
| ○ 灰空心 + 虚线分叉 | 已合入·待清理（零损失） | `mergedInto` ∧ 不脏 |
| ◇ 灰菱形 | 外部（非 Roam 创建） | `external` |
| ◎ 蓝 | 主工作区 | `isMain` |

实现上主干**不能画进每行的 SVG**——行高随内容变，画进去必断。主干是整行高的绝对定位元素
（`::before`，`left:15px; top:0; bottom:0`），SVG 只负责「从主干拐出来的那一小段 + 节点」，
钉在行顶固定偏移 22px 处。

### 8.3 就地操作

三个动作全部在行内做完，不再跳面板：

- **对比 base** → 打开 Git 面板并**直接定位到这条 worktree 的「对比 base」**，不让用户自己找。
- **合并回 base** → 行内 `Dropdown.Button`（squash 默认 / merge / rebase），复用现有 `/git/worktree/merge`。
- **已合入·待清理**的动作是「看合入的内容 + 一键清理」，**不是「合并」**——已经合过了，再给合并按钮是误导。
- **external** 明确不给合并/删除（roam.* 身份缺失，动它是越权），只留只读的对比。
- 新建 / 清理残留 / 跨仓库总览提到顶部工具条。

### 8.4 三处展示的分工

| 位置 | 职责 |
|---|---|
| 项目页 Worktree tab | 并行任务的**全景**：分叉图 + 会话 + 收尾决策。日常主入口 |
| Git 面板 分支页 | 当前仓库的**引用视角**：新增一段 Worktree，与分支并列 |
| Worktree 抽屉 | 只留**跨仓库总览**与残留清理；项目内的事都在项目页做完 |

配套两处小改动：

- Git 面板「分支」页在 本地/远端/标签/储藏 之外**再加一段 Worktree**，当前所在的那个高亮（「你在这」）。
- 提交树里，被 worktree 占用的分支徽标带一个 `⧉` 角标，点它跳到那个 worktree 的会话
  （没有会话就跳项目页对应行）。数据现成：`for-each-ref %(worktreepath)`，不用新接口。

## 9. 落地约束

1. 全部文案走 i18n（`git.graph.*` / `git.refs.*` / `git.detail.*` / `git.action.*`），中英同步补齐。

3. worktree 会话的「对比 base」tab 与底部「合并回 base」操作条原样保留。
4. 手机上危险操作再过一次确认；⋯ 与长按都出**底部动作面板**（拇指区），每项 40px 高。
5. 文件结构：`frontend/src/git/{graph.ts, parts.tsx, GraphView.tsx, RefsView.tsx, CommitDetail.tsx, AskModal.tsx}`，
