底部状态条 — 一条 24px 的常驻读数

在壳的最底下加一条 24px 的常驻细条，长得像 VS Code 的状态栏： 左半是工作区（这台机器、后台在跑什么、分支、要你处理的事、主机撑不撑得住）， 右半是你此刻正对着的东西（文件的行列/编码/语言、会话的 pane 尺寸与模型、镜像的设备）。 左半不随页面变，右半随页面换——这正是 VS Code 二十年没改过的那条分界。 平静时整条一种灰，只有越线的那一格上色。 条是壳，格是注册进来的：宿主一格都不硬编码，连 CPU / 内存 / 磁盘那几格都由 roam.host-monitor 插件走公开贡献点注册——第三方插件用的是同一条路。

01为什么要它：这些数字今天都不在屏幕上

Roam 现在有四个地方在报「状态」，但没有一个报这台机器本身：

今天在哪报什么问题
WorkspaceTopbar在线 / 离线小圆点、终端数只说「网通不通」，不说机器怎么样；且手机没有顶栏
Navigation 底座机器切换器 + 中心红点、P2P 链路轨态（收起 / Focus / 非 large）下只剩一个头像，名字和延迟都看不见

这就是 2026-08-22 那次的形状

30 GB 的机器被一个 Claude Code 进程吃到 15.5 GB，界面上从头到尾没有一处 说过内存在涨；发现它是因为机器卡死了。同一个形状在中心那次也出现过：goroutine 从 1518 爬到 18298，十几个小时无人发现——R1 内存护栏 给了限额和曲线，但曲线要点进去看。常驻可见是护栏缺的那一半。

02准入规则：什么有资格占这 24px

条上能放二十五格，但同一时刻只出现十来格。谁进谁不进，靠三条硬规则—— 第一条正是 VS Code 那条左右分界：

1
左半登载「不看就会错过」，右半登载「你此刻在动的那个东西」 左半是工作区作用域：机器、后台任务、分支、待办、主机负载——换页不变。 右半是上下文作用域：打开的是文件就给行列/编码/语言，聚焦的是会话就给 pane 尺寸/前台命令/模型，看的是镜像就给设备与分辨率。一格只属于一半， 两边都想要的格子说明它的作用域没想清楚。
2
平静时只有一种颜色 全部 --text-dim。越阈值的那一格才变 --warn / --danger。 一条平时就有绿有蓝有黄的条，第四天起就没人再看它了。VS Code 那条整条蓝底我们不抄， 理由见 §04。
3
每一格都要有去处 点分支去 Git 面板、点待办去那一页、点内存去护栏面板、点行列跳转行。 只读的格（编码、换行、pane 尺寸）也要能点开看到出处， 一个只能看不能点的数字，看见了也不知道下一步干什么。

04照着 VS Code 抄什么，不抄什么

VS Code 的状态栏是这类控件里被磨得最久的一个，它的分组、位置、交互都值得直接照搬。 逐项过一遍——抄的是位置和语法，不是内容：

VS Code抄不抄Roam 对应
最左的远程指示器（实心块 ><）抄 机器格。不是本机时整格上实心强调底——这是全条唯一一块实心色，理由与 VS Code 一样： 「你现在动的不是本地」是最容易搞错、代价最大的一件事
分支 + 同步（main ↓2 ↑1）抄 分支格。/git/status 今天就返回 branch/ahead/behind，箭头用 ArrowUp/ArrowDown 两枚 SVG，不是 ↑↓ 文字
问题（错误数 / 警告数）抄形式 待办格。Roam 没有编译错误，但有等价物：n 待确认（会话卡在权限确认）· n 待收尾（已合入未清理的 worktree）· n 发现（插件 findings）。语法和 VS Code 一样：一个数字，点开是清单
端口转发（Ports）抄链路格：直连 / 隧道 / P2P + 当前速率。侧栏底座那枚 LinkStatus 搬过来
后台任务进度（转圈 + 一句话）抄 后台格。Roam 的后台活儿比 VS Code 还重：系统镜像 2G 下载、模拟器冷启 37s、插件跑、P2P 传文件、Git fetch
只读锁抄打开的文件没有写权限时出现一格「只读」，省得改半天存不进去
Ln, Col（点击=跳转行）抄文件页就是 Monaco，行列与「已选 n 行」原样搬，点击开跳转行
缩进 / 编码 / 换行 / 语言抄四格照搬。缩进和语言可点（改），编码和换行只读
通知铃铛（最右）抄插件通知（/plugin/notifications）。位置也照搬——最右，最后一格
Copilot 状态抄，且加厚 Agent 格：当前会话跑的是 Claude 还是 Codex、什么模型、上下文用掉多少。 这是 Roam 比 VS Code 更该有的一格——那边 agent 是插件，这边 agent 是主角
Prettier / 格式化程序不抄Roam 不做格式化
反馈笑脸不抄VS Code 自己也删了
整条蓝底（无文件夹时紫底）不抄见下
右键逐格隐藏的长菜单抄一半给「显示哪些格」的开关（设置页 + 状态条右键），但不做拖拽排序——顺序固定才有肌肉记忆
扩展贡献状态栏项（createStatusBarItem）抄，但改成声明式 这份设计的核心，见 §05。VS Code 的扩展跑在扩展宿主进程里、能直接 new 一个状态栏项； Roam 的插件是外部进程（plugin run 每次一个短命子进程），不可能让它渲染我们的 DOM。 所以贡献点是声明式的：插件在 manifest 里声明格子，只提供数据，宿主用固定的四种渲染器画
—加主机负载（CPU / GPU / 内存 / 磁盘 / 温度 / 网络）。VS Code 这归扩展—— Roam 也归扩展：roam.host-monitor 是个 builtin 插件，早就在采这些数（还带 12 分钟趋势和一整页仪表盘）， 这次只是让它把六格注册到条上。这台机器就是干活的机器，而它被一个 agent 吃爆过（R1）
—加蜂群、会话数、镜像设备——Roam 独有的三样上下文

那条蓝底为什么不抄

VS Code 用整条蓝区分「打开了文件夹 / 没打开」，是二十年前留下的身份色。 Roam 抄过来有两个实际问题：壳里已经有强调蓝在导航选中项和主按钮上，底部再铺一整条会把视线钉死在最底下； 更要命的是深色主题下终端就贴在它上面，一条饱和蓝紧挨着一屏 --bg-term 非常吵。 所以我们反过来：平静时一整条灰，实心色只留给「不是本机」那一格—— 把 VS Code 那块实心色的信息量留下，把它的面积丢掉。

05注册制：条是壳，格是注册进来的

条上两类格并存：系统格（宿主自带，随二进制走，装不上也卸不掉） 和插件格（注册进来的，可装可卸）。宿主本身不画任何一格—— 它只提供一条 24px 的横槽、四种渲染器、一套阈值判定和一套折叠规则； 两类格共用同一套契约，但不是同一等公民，差别下面一张表说清。 contributes.statusItems 是新的贡献点，和今天的 commands / configFields / notificationSinks 并列 （05-manifest §2 那张表加一行）。

为什么系统格不做成插件

「全都是插件」听着更纯粹，但会付两笔代价：机器格、待办格这些必须在第一帧就有值， 走 plugin run 意味着开局先空半秒；而它们的位置是肌肉记忆的锚， 一旦进了「按 priority 排序的尾段」，装个插件就可能把机器格挤走。 反过来，主机负载做成插件是对的——它本来就是插件，采集要读 /proc、要调 nvidia-smi、要跨调用存计数器，那是插件该干的活，不是壳该干的。

主机监控是第一个用户，而且它已经在那儿了

roam.host-monitor（plugins/hostmonitor/）是个 builtin 插件， 今天就在采 CPU / GPU / 内存 / 磁盘 / 网络 + 12 分钟趋势，插件页里还挂着一整页仪表盘。 这次不写新后端、不加新接口——只在它的 manifest 里多声明六个 statusItems，那六格就出现在条上了。它走的是第三方插件将来要走的同一条路， 没有任何特权通道。

贡献点长什么样

系统格（宿主自带）插件格（注册进来的）底线只是这份稿子的标注，真实界面上没有
两类格并排。机器 · 分支 · 通知 · 版本是系统格；中间六格是内置插件 roam.host-monitor 注册的；CI 通过那格来自第三方插件 acme.ci（装了它、并且在设置里打开之后才出现）。三者在条上长得一模一样，这正是目的——装了 N 卡就多一格 GPU，没有就少一格，判据是 nvidia-smi 取不取得到，而不是宿主里的一个 if。

四条硬约束

1
插件给数据，不给 DOM VS Code 的扩展跑在扩展宿主进程里，可以直接造一个状态栏项；Roam 的插件是 外部进程（plugin run 每次一个短命子进程），让它往我们页面里塞标记 等于把 XSS 写进设计。所以贡献点是声明式的：render 只能从 text / gauge / dot / progress 四选一，图标只能按名字从 icons.tsx 取，不能自带 SVG、不能自带颜色。 这和 configFields「插件零前端、表单由宿主渲染」是同一个思路。
2
红黄绿由宿主判，不由插件说 插件报 value，宿主拿声明的 thresholds 判 severity。 要是让插件自己说「我现在是 danger」，每个插件都会把自己染红—— 第三个红格出现的那天，这条就报废了。sustainSec 也在宿主这边算（CPU 那条 60s 滞后，见 §08）。
3
位置由段决定，不由插件抢 内置格的位置是写死的——机器永远第一，版本永远最后，肌肉记忆靠这个。 插件格只能落进两个段：left-tail（左半尾）和 right-head（右半头）， 段内按 priority 从大到小、同分按 id 字典序（稳定，不会因为装插件的顺序抖动）。 priority 只在段内有意义，再大也插不到机器格前面。
4
一个 provider 崩了，只熄它那几格 宿主永远不 await 插件来渲染第一帧：条先画出来，格子有值了再填。 命令超时 1s、连续失败 3 次熄灯并退避到 60s 重试、值超过 3×refresh 判 stale （变暗置 --，见 §08 ④）。插件死了条不动，这是底线。

插件报了一个系统格已经在报的东西

比如装了个插件也报 CPU。不拦——拦了就得维护一张「哪些语义已被占用」的清单， 而那张清单永远不全。做法是：系统格永远占它的固定槽位，插件那一格落在尾段， 两个 CPU 一左一右并排显示；设置页里两条都列着、各带来源，你自己关掉一个。 看得见的重复比看不见的覆盖好。

拉与推

默认拉：宿主按 refresh 调 POST /plugins/<id>/run，从返回的 JSON 里按 path 取值—— 这正是主机监控面板今天在做的事，一条新接口都不用加。 常驻插件（runtime.resident）可以声明 "push": true， 改由 SDK 的 roam.status.set(itemId, value) 主动推（IM 桥那种长连接插件适合这个）。 两条路进同一张注册表，渲染侧不区分。

六个 provider，各注册哪些格

五个系统 provider 加一个插件，用的是同一个贡献点结构——这是整件事成不成立的判据：

provider注册的格
roam.core机器 · 中心 · 会话 · 通知 · 版本
roam.git分支 · 改动
roam.tasks后台 · 待办 · 蜂群
roam.host-monitor 插件CPU · 内存 · 磁盘 · 温度 · GPU · 网络

差别只有两处：内置 provider 的数据源是进程内的 state（不是 plugin run）， 位置可以落在固定槽位而不是两个尾段。要是宿主自己的格走后门，这套注册制两个月就烂了—— 到时候没人记得那条公开路径还能不能用。

配套还要动一处 manifest 规范：激活事件加 onStatusItem:<id> （第一次要渲染这一格时才拉起插件），贡献点表加 statusItems 一行，分期 v1。

⑤ 手机镜像页。右半只剩设备与分辨率。后台格在数模拟器冷启的秒数——那件事要 37 秒，没有这一格的时候，界面上只有「转圈」和「你是不是卡住了」。

10手指与手机

粗指针：整条长到 44，格子减到三个

AGENTS 的规矩是「用伪元素撑命中区，不要撑视觉尺寸」。这里是那条规矩的例外， 而且必须是例外：状态条上方紧贴着页面内容，往上撑 20px 的伪元素会在每一页的最后一行 盖出一条点不到的死区。所以这里反过来——把条本身长到 44px，同时只留三格： 机器、当前最重的那一格、会话数。

平板 / 触屏笔记本（data-pointer="coarse" 且 desktop 档）。三格，每格自带 ≥44 的命中高度，格间距 --sp-3，相邻两枚的间隙比 44 再多 4px。

手机：不常驻，只在出事时来一条

手机底部已经叠了两层：会话坞 50px + 底栏 6 格，共用一个 fixed 容器。 再加一条常驻状态条就是第三层——360px 宽的屏上，底部会吃掉三分之一。所以手机上：

  • 平静时不渲染。一个像素都不占。
  • 任何一格进入 danger 时，在会话坞之上插一条 28px 的单行告警， 只说那一件事：内存 30.2/32G · 正在换出。点它进护栏面板。
  • warn 档不打扰手机。手机不是运维终端，黄色的东西留给你回到电脑前再看。
  • 右半的上下文格手机上一格都不出。「未保存」「行列」这些归各页自己的工具条—— 文件页那颗黄点和保存钮今天就在，状态条不去接管它。
  • 完整读数进「更多」sheet 的第一段：主机状态，一行一格， 行高 ≥44——那是手机上看这些数字的正规入口。

状态条不许自己去轮询

二十五格，如果每格自己拉一条接口，就是二十条新轮询——而 18 号设计刚刚删掉过一套 「概览每 6s 对 ≤14 个会话各发 3 条请求」的轮询。规则： 内置 provider 一律订阅 App 已有的 state，一条新请求都不发； 只有插件 provider 才按 refresh 拉，而且拉的是整个快照—— 主机那六格共用一次 host-monitor.stats 调用，不是六次。 document.hidden 时全停。拿不到的数据就不显示那一格， 不为了填满一条状态条去加一条轮询。

不做什么

  • 不做曲线。24px 里画 sparkline 只能画出噪音；历史归中心页与护栏面板。
  • 不做拖拽自定义顺序。顺序固定才有肌肉记忆；能配置的只有「显示哪些格」。
  • 不做进程级排行。你能操作的单位是会话，不是 PID；小卡里给的就是会话。
  • 不做通知。状态条是被动的。要主动推送归插件（roam.cron 那条路）。
  • 不为一格加一条轮询。见 §12。
  • 不让插件跑前端代码。贡献点是声明式的，渲染器只有四种，图标按名字取。见 §05。
  • 不让插件自己说自己是红的。severity 一律宿主按声明的阈值判。
  • 不在手机上常驻。见 §10。

一句话

一条 24px，左半十三格右半十二格，同一时刻只出现十来格，平时一种灰。 形状照抄 VS Code——左边是你看不见的东西，右边是你正在看的东西。 但条上两类格并存：系统格随二进制走、占固定槽位、第一帧就有值；插件格注册进来、落尾段、可装可卸。主机那六格属于后者——由已经存在的 roam.host-monitor 插件走公开贡献点注册， 第三方插件走同一条路、受同一套预算约束。宿主只负责一条槽、四种渲染器和一套折叠规则。
