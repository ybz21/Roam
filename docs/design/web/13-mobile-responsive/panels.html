手机二级页：Git / Worktree / 返回键

13 §6 的塌陷表里还剩两行没做：Git 面板与 Worktree。它们在手机上仍然是桌面抽屉—— 不是「窄了点」，是三个功能性故障：盖住底栏、不吃安全区、按返回键没反应。 顺带两件事一起了：手机上没有任何导航入口能到会话列表页；四处 hover 才出现的操作在手指档摸不到。

  • 同一个 Git 面板有两套壳。会话页走 FloatingFileDrawer（fixed; width:min(420px,92vw); z-index:1200）， 项目页是另一份手搓的 zIndex:1000 遮罩 + min(520px,94vw) 右侧面板。
  • Worktree 是 Drawer width='100%'——13 §4.3 点名的「既不是页也不是 sheet」： 从右横切进场、右上角一个 ×、底部不让安全区。
  • 返回键没人接。MobileSubPage 没有任何 history 处理；MobileSheet 的注释写着 「接管返回」，实际只监听了 Escape——手机上没有 Escape 键。

五、返回键：一个共享 hook

useBackDismiss(enabled, onDismiss) → depth

打开            pushState(history.state, '', location.href)   ← URL 不变，路由收不到 hashchange
                push { id, onDismiss, closing:false }

UI 关闭         onClose()            ← 先同步关，无延迟
（← / × / 遮罩）  frame.closing = true
                history.back()       ← 必须退掉这条记录，否则留下死记录：
                                        用户按一次返回没反应、再按一次直接退出

返回键          popstate → 弹栈顶一帧
                closing === true  ⇒ 吞掉（是我们自己发的）
                closing === false ⇒ onDismiss()
                一次 popstate 只退一帧 ⇒ diff → Git → sheet 按一次退一层

打开态卸载       同 UI 关闭，但不调 onDismiss；不是栈顶就只摘帧、不碰 history

兜底            栈非空时发生 hashchange（路由变了）
                ⇒ 对所有存活帧调 onDismiss 并清栈——覆盖层在路由变化后一定是过期的

不要往 history.state 里塞标记再读回来：App.tsx 的 setHashParams 每次开关终端标签都跑一次 replaceState，会把标记抹掉。模块级 LIFO 栈是唯一事实来源。
只在手机档启用——劫持桌面浏览器的返回键是行为变更；桌面继续走 Escape。

六、自审：画完之后自己挑的毛病

  1. 第一版 Git 二级页头我放了「Git · roam」两段。但页头下面第一行就是分支 chip， 项目名在项目页进来时是废话（你就在那个项目里）、在会话页进来时又不如分支准确。 删掉，只留「Git」+ 分支 chip。
  2. 差点把 ＋/↻ 留在 Worktree 的目录行里。那行原本是「目录框 + ＋ + ↻」三件套， 360 上目录框会被挤到 180px、路径几乎全截。＋/↻ 上提到页头当 44 图标，目录框独占一行。 顺带这也让页头的图标位有了统一用途（Git 是 ↻/⋯，Worktree 是 ＋/↻）。
  3. diff 详情页最初画了「← Git」。返回标签写上一层的名字看着贴心，实际会误导： 用户以为点它回 Git 列表，其实两层都可能被返回键退掉。返回箭头不带文字，标题写当前文件名。
  4. 「会话」放进「工具」段是错的。工具段是浏览器/手机/插件/设置——外围能力； 会话是工作区主线，和概览/项目/文件同级。单开一段「工作区」，排在工具之前。
  5. 键盘态那帧提醒了一件事：提交区不能只靠 --kb 抬起。 iOS Safari 没有 VirtualKeyboard API，--kb 只能从 visualViewport 推，有 30px 噪声底； 所以写 max(var(--kb), var(--safe-b)) 而不是 var(--kb)——键盘收起时至少还有安全区。
  6. 桌面帧一开始没画。但这次改的是三个调用点的容器，最大的风险恰恰是「手机修好了、桌面变了」。 补一帧标「不动」，并把项目页 Git 会继承浮动面板的阴影这件事写进风险—— 那是唯一一处桌面视觉可能变化的地方，要么明示接受，要么给个开关。
  7. 返回键的状态机里，最容易漏的是「UI 关闭也要 history.back()」。 漏了它每开关一次就留一条死记录，用户按返回「第一次没反应」。 这条单独画进状态机，不是写在注释里。

七、落地后的两处修正

  1. Git 的 ⋯/↻ 最终落在分支行右端，不是页头。图纸把它们画进了二级页页头， 但页头是 MobileSubPage 的、图标却属于 GitPanel 内部状态（⋯ 是带菜单的 Dropdown），跨component 传上去要给二级页开一个 actions 插槽、再把面板内部的 JSX 挪出去。实测把标题行整行去掉、两枚图标并进下面的分支行，效果一样（内容还往上提了 62px）， 改动只在 GitPanel 内部。Worktree 的 ＋/↻ 同理，保留在它自己的目录行里。
  2. StrictMode 会把返回键的 push/back 打乱。开发态 mount→unmount→mount 是同步跑完的， 退帧发出的 history.back() 却是异步落地，中间第二次 mount 又 push 了一条—— 两者交错会把当前位置挪到别人的记录上，表现为「按一次返回退了两页」（实测复现）。 解法：退帧的 back 延到微任务再发，同一 tick 内又压帧就直接复用那条记录， 双挂载的净效果变成 0 次 history 操作。这条写进了 useBackDismiss 的单测。
