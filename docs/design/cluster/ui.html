Roam · Cluster · 视觉设计 v0.2

多机管理 —— 一个入口管所有开发机

0. 一分钟看懂

连了云端 Broker 之后，浏览器里多出一个 当前机器 的概念：左侧栏底座那枚「当前设备」按钮 变成机器切换器，页头的眉标行多一枚机器芯片，终端标签前面多一枚机器方章。 除此之外 什么都没变——没有新增顶栏、没有新增一层壳、没有第五支颜色。 没连 Broker 的单机用户，界面和今天像素级一致。

  • 切机器 = 换浏览范围：项目 / 会话 / 文件 / Git / 浏览器 / 手机整体换到那台机器。 唯一的例外是工作台顶上那层——「需要你」行动队列永远是全机器的（§6）。
  • 终端不跟着走：已打开的终端各自钉在自己的机器上，带方章，切机器不关它们——那是正在跑的活。
  • 机器身份只有两个锚点：侧栏底座（我连着谁）和页头眉标（这一页是谁的）。多一处就是噪音，少一处就会误删。
本稿与 2026-07 那版（docs/design/cluster/多机切换交互设计.md）的关系： 架构结论仍然有效，界面结论全部作废。那版写在 App.tsx 还是一个平铺 antd Menu、 手机还没有底栏六格、侧栏还没有轨态的时候；今天这三件都变了，照那版做会打架。 第 1 节逐条对照。

1. 旧稿的六条结论，为什么今天要重画

旧稿结论今天的 UI 已经是什么样新结论
切换器挂侧栏顶部，Logo 正下方 侧栏默认是 64px 轨态（#182），顶部只剩一枚 34px 标；底座已经有一枚主机图标的 「当前设备」按钮（shell/Navigation.tsx 的 .tt-nav-account） 切换器就是底座那枚按钮。它本来说的就是「你连着的这台机器」，多机后它终于有了名字。 顶部不动——那里是品牌，不是状态
手机加一条 36px 常驻置顶细条 13 / 17 号设计特意拆掉了手机顶栏；底部已经是「六格 + 50px 会话坞」， 竖向空间是最贵的资源 不新增细条。机器进页头眉标（.tt-pagehead .kicker）成一枚可点芯片， 每页都有、一行不占
每台机器 hash 出一个颜色，标签左侧色点 AGENTS.md 硬规矩：全站只有四支色（蓝/绿/黄/红），且蓝绿各只有一支。 #186 之后已经有第五支——蜂群紫 --swarm，还是被收拢过一次才只剩一处的 机器不给颜色，给机器方章（.tt-nodemark，一个汉字或两个字母）。 颜色只留给状态：绿在线 / 黄降级 / 灰离线
标签文字 公司·build 标签已经是两段式 项目 · 会话（DockTitle）， 窄了先截项目名 不加第三段名字。方章 + 原有两段；机器全名进 title 和终端头部那一行
/nodes 进常驻导航 NAV 导航分「工作区 / 工具」两组，#186 之后共 7 项； 手机底栏 4 格 + 更多，空出的一格特意没补人 连了 Broker 才出现在「工具」组；手机只在「更多」里。单机用户看不到这一项
跨机器总览留到 P3 概览页没有了（#186 / 18 设计）：并进项目页成了唯一首页「工作台」， 独有的「需要你」行动队列和活动轨挂在项目墙顶上 不做「全部机器 / 当前机器」开关。工作台上下两层各归各的： 行动队列跨机器，项目墙跟当前机器（§6）

2. 机器身份：一枚方章，三种状态

多机界面最容易失控的地方是「给每台机器一个颜色」——四台机器四支色， 和状态色（绿在跑 / 黄等输入 / 红失败）在同一枚标签上打架，一眼分不清那个绿点说的是 「机器在线」还是「Agent 在跑」。所以本稿把两件事拆开： 身份看形状（方章里的字），状态看颜色（点）。

为什么不用头像/图标区分机器：机器数量是用户定的（2 台还是 20 台）， 图标集不可能覆盖；而名字的头一个字是用户自己起的，认得最快，也永远够用。 重名（两台都叫「云…」）时在列表里追加 hostname 消歧，方章本身不去凑第二个字。 方章同时是 /nodes 卡片的图标、切换器的行首、终端标签的前缀——同一个东西全站一个长相。

3. 桌面：机器切换器长在侧栏底座

底座今天从上到下是：P2P 链路状态 → 终端开关 → 当前设备 → 收起。 多机后「当前设备」这一行换成机器切换器：方章 + 名字 + 状态点，点开是机器列表。 设置 / 关于 / 主题 / 退出仍在同一个菜单的下半段——它们本来就挂在「这台设备」上。

4. 第二个锚点：页头眉标就是机器面包屑

.tt-pagehead 的眉标行今天写的是「工作区」「工具」这类分组名—— 信息量约等于零。多机后它变成 机器芯片 · 分组名：桌面手机同一个组件， 一次改动两端都有。这就是旧稿要为手机单独加一条 36px 细条的那个需求， 只是它其实已经有地方放了。

单机时这枚芯片不渲染，眉标退回今天的「工作区 / 工具」。 这条对所有多机元素都成立：没连 Broker 就当它不存在，一处都不留。

5. ⌘K：搜索一定是跨机器的

这一条是整份稿子里唯一一处「多机让功能变强」而不只是「变得能切」的地方， 所以它不是 P3 的加料，是 P1 的地基。 单机时代 ⌘K 是「找到就跳过去」；多机后如果只搜当前机器，用户得先自己想起来 「那个文件在哪台机器上」——而这正是多机管理本该替他消灭的负担。 一台机器上找不到就换一台再搜一遍，是把路由工作推给了人。

  • 按机器分组，不给远端结果降权。如果给别台机器的命中乘一个 0.7， 「我明知道那东西在 GPU 机上」的搜索永远排在本机的噪音后面。 改成分组：本机一组在最前，其他机器各一组带方章段头——顺序上偏向本机，分数上不动它。
  • 慢机器不许拖慢搜索框。结果逐台流式并进来：本地条目先出（今天就是这样）， 近的机器几十毫秒到，远的机器后到。一台 200ms 的机器不能让每次按键都等 200ms。
  • 没搜到的机器要说出来。底部状态行写「树莓派 未响应」—— 静默丢弃比搜不到更糟：用户会以为那台机器上真没有。
  • 名字搜索默认全机器；内容搜索（rg）默认只本机，底部给一枚「在全部机器里搜内容」。 内容搜索比名字搜索贵一到两个数量级，扇出到 20 台机器等于同时点着 20 个 rg—— 显式触发的心智今天已经有了（面板里的全文搜索本来就要手动点），沿用即可。
  • 点开别台机器的结果 = 隐式切过去：文件/项目类直接切并打开； 会话类走 §7 的弱联动气泡问一句。
这条决定了一件必须在 P1 就做对的事：结果的 id 和 action.target 都要带 nodeId。今天 rows.ts 的 dedupeByKey 按 kind + id 去重——两台机器上都有 build 会话、都有 ~/codes/roam/README.md，不带 nodeId 就会被合成一条， 而且合掉的那条无声无息。这和终端标签键 (nodeId, name)（技术稿 §6）是同一笔账，一起还。

6. 工作台：上层跨机器，下层跟当前机器

概览页已经没有了——#186 把它并进项目页，#/projects 成为唯一首页 「工作台」，概览独有的「需要你」行动队列和最近活动轨挂在项目墙顶上。 这对多机是件好事：旧稿要在概览上加一个「全部机器 / 当前机器」开关， 而合并之后这一页天然就分成了语义不同的两层，各归各的，不需要开关。

#186 顺手把跨机器工作台从"不可行"变成了"一台一条请求"。 合并前，概览对最多 14 个会话逐个打 /claude /codex /capture， 6 秒一轮、峰值 42 条请求——乘以 N 台机器直接不用谈。 #186 把这些字段并进了 /projects 一条请求（top[] 2→3、 running 放宽成 claude|codex、waiting 带出尾行摘要）， 前端那套轮询整段删除。于是跨机器工作台 = N 条请求 6 秒一轮，十台机器也才十条。

7. 终端：标签钉死在机器上

终端是长活上下文，切机器绝不能关掉它们——瞄一眼另一台机器的状态就丢掉正在跑的 Claude 会话，这在实际使用里不可接受。所以标签各自带方章，跨切换保留。
